# Extraction Pipeline Stage-Contract Audit

**Status:** Documentation-only contract baseline  
**Audited integrated revision:** main at 03f77ff4430d1a9015584ca252d2c4c7dba23308 (AP-DIAG-049 integrated)  
**Comparison:** open PR #42, AP-DIAG-FIX-012, head d63379176b2679b37feda10c77883aa9e6688df9  
**Scope:** source-level audit of ExtractionPipeline::run() and the aggregators it invokes. No production code changes are part of this audit.

## Purpose and acceptance rule

This document turns pipeline ordering and sequence independence into explicit acceptance contracts. Subsequent work packages must reference this document and satisfy the affected rows. A local build or passing test suite does not waive a violated stage contract.

**Sequence invariant** means that permuting an equivalent input collection cannot change the semantic result. A different serialization order alone is not a semantic difference. IDs may identify records, join artifacts, and preserve provenance; opaque or source-derived IDs must not choose a geometric representative, decide a tie, determine a traversal order that changes graph meaning, or resolve conflicting evidence.

**Ordering status**
- **PASS**: required input artifacts and semantic fields are available before consumption.
- **VIOLATION V1/V2**: a producer runs too late for a consumer, or a semantic field is consumed before its authoritative producer.
- **CONTRACT RISK**: the current output is order-sensitive, relies on ID order for a semantic decision, or assumes uniqueness without enforcing it.

## Confirmed producer-consumer ordering violations

### V1 — Connector geometry is produced too late for conductor ownership

Integrated main runs GeometryOwnershipClassifier before ConnectorGeometryDetector. Ownership therefore cannot use connector-body regions to classify connector housing strokes before topology. This is the class-level failure exposed by AP-DIAG-049, not a coordinate-specific defect.

**Acceptance requirement:** connector geometry required for ownership must be produced before ownership and passed as an explicit classifier input. Housing suppression must require independent boundary evidence, and conductors meeting connector boundaries must remain eligible. AP-DIAG-FIX-012 moves connector detection earlier on its proposed branch, so it addresses this ordering violation in principle; its resulting ownership and topology still require the normal evidence review.

### V2 — Native connector-terminal association consumes endpoint semantics before the semantic producer

The connector-pin association stage and ConnectorTerminalModelBuilder::build_native run before TerminalLocationDetector, TerminalRecognizer, TerminalSemanticEvidenceBuilder and EndpointSemanticReconstructor. EndpointReconstructor initially sets every generated candidate to GeometricConductorEnd. The later component/ground/connector semantic classification is therefore unavailable to the native builder's stated guard against overriding an independently resolved boundary.

**Acceptance requirement:** separate geometry-only pin/crossing observation from semantic endpoint association. Resolve or materialize connector-terminal associations only after EndpointSemanticReconstructor has produced the authoritative endpoint kinds, or establish another explicit upstream producer for the exact semantic field the guard consumes. Add regression coverage for a geometrically matching endpoint later classified as a component terminal or ground so it cannot be promoted to a connector terminal by the earlier placeholder value.

The current PR #42 branch moves connector detection before ownership but, at the audited head, still performs connector association/materialization before EndpointSemanticReconstructor. V2 is therefore outstanding on that branch.

## Cross-pipeline sequence-sensitivity findings

These are ordering-independent of V1/V2 and must not be hidden by moving one detector earlier.

1. **Conductor geometry aggregation:** ConductorNormalizer has first-wins duplicate handling and first-pair collinear merging. Canonical-sort by undirected geometry before both operations; settle same-geometry evidence by explicit strength/provenance rules; calculate stable IDs only after merged geometry is final.
2. **Graph representative and greedy pairing:** TopologyReconstructor now canonicalizes segment geometry (FIX-009), but GapInterpreter and Wire reconstruction still contain traversal/first-arrival choices. Canonicalize endpoints and incident edges by canonical geometry before traversal, and make ties/conflicts explicit rather than ID-order-dependent.
3. **Evidence reducers:** RejectedGeometryClassifier, TopologySemanticResolver when populated, CircuitRoleResolver, ComponentIdentityEvidenceBuilder, SymbolFamilyRecognizer and connector-native semantic materialization contain tie, first-wins, last-wins or multiplicity assumptions. Resolve grouped evidence by total-order canonical evidence content, aggregate equivalent provenance, and retain same-strength disagreement as conflict.
4. **Detection deduplication:** ShapeDetector, TextRegionDetector and ConnectorGeometryDetector perform suppression/grouping before their final sorts. Sorting outputs afterward cannot reverse a first-wins choice made during candidate creation. Canonicalize candidates before suppression and grouping, and specify a deterministic quality/geometry representative rule.
5. **Output IDs are not a canonical geometry order:** Several artifacts are sorted by ID for serialization. IDs can include source, page or upstream IDs, and must not be used as the geometric traversal/representative rule where order changes model meaning.

## Acceptance baseline for subsequent work packages

A work package that changes stages, evidence aggregation, topology, endpoint/terminal identity, connector ownership, wire identity or electrical-net semantics must:

1. Name the affected stage row(s) and identify each consumed artifact's authoritative producer.
2. Demonstrate that every semantic input exists before consumption; any intentional exception must name its narrower evidence contract.
3. For every multi-input aggregation, state its permutation-invariance rule. Where order matters, canonicalize by undirected geometry or canonical evidence content before reduction; identifiers are for joins and traceability only.
4. Preserve unresolved/conflicted outcomes for equal-strength contradictory evidence instead of selecting a winner by first arrival, last arrival, or ID.
5. Add permutation/regression tests for the affected aggregation and confirm that changing IDs or input vector order while holding source geometry/evidence constant does not change semantic geometry, topology, endpoint pairing, wire identity or electrical-net membership.
6. Run the AP-specific evidence review where applicable, then the clean Release build, full CTest suite, diff check and the mandatory main-only tools/dx-ap-gate.ps1 after normal integration.

This document records the source-level contract baseline. It is not a claim that the current pipeline already satisfies every row, and it does not substitute for runtime validation or acceptance evidence.
